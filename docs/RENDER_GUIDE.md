# 🚀 DreamPocket Render 서버 운영 및 관리 가이드 (Operations Manual)

DreamPocket 웹 플랫폼과 텔레그램 봇의 백엔드 시스템은 현재 클라우드 호스팅 서비스인 **Render** 위에 **Docker(도커)** 컨테이너 기술과 **Persistent Disk(지속성 디스크)**를 결합하여 안정적으로 24시간 가동 중입니다. 

이 문서는 대학생 창업가인 대표님이 혼자서도 서버를 모니터링하고, 관리하며, 비용을 통제할 수 있도록 꼭 필요한 핵심 내용만 쉽게 정리한 가이드라인입니다.

---

## 📌 1. 전체 시스템 아키텍처 개요
DreamPocket은 Render에서 제공하는 **Blueprint (코드형 인프라)** 방식으로 가동되고 있습니다. 
*   **Blueprint란?** `render.yaml` 파일에 명시된 설계도대로 Render 서버가 알아서 데이터베이스 디스크를 생성하고 서버를 조립하는 스마트한 인프라 관리 기술입니다.
*   **Docker 가동 방식:** `Dockerfile`에 정의된 내용에 따라 Playwright(가상 크롬 브라우저) 구동에 필요한 모든 리눅스 라이브러리가 미리 세팅된 상태로 서버가 구동됩니다.
*   **영구 디스크 (Persistent Disk):** 서버가 재부팅되거나 소스코드가 수정되어 새로 배포되더라도, 회원 정보와 수집된 장학금 데이터가 저장되는 SQLite 데이터베이스 파일(`/app/data/antigravity_bot.db`)은 삭제되지 않고 안전하게 보존됩니다.

## ⚙️ 2. 환경 변수 (Environment Variables) 관리
서버의 민감 정보(API 키, 비밀번호 등)는 코드에 노출하지 않고 Render의 **Environment**에 설정하여 안전하게 보호하고 있습니다. 

### 🔑 관리해야 할 핵심 환경 변수 목록
환경 변수를 수정하거나 확인하고 싶을 때는 **Render Dashboard ➔ Web Services ➔ `dreampocket` 클릭 ➔ Environment 탭**으로 이동합니다.

| 환경 변수명 | 목적 및 설명 | 권장 값 및 예시 |
| :--- | :--- | :--- |
| `FLASK_ENV` | 플라스크 실행 환경 설정 (보안 강화) | `production` |
| `TELEGRAM_BOT_TOKEN` | 텔레그램 봇과 연동하기 위한 토큰값 | `8540235732:AAHRJQLL...` (BotFather 발급) |
| `GEMINI_API_KEY` | 장학금 공고 정밀 분석을 위한 구글 AI 키 | `AIzaSyBMVzpxsztw6b...` (Google AI Studio 발급) |
| `ADMIN_USERNAME` | 관리자 페이지(`/admin`) 로그인 아이디 | 예: `dreampocket` |
| `ADMIN_PASSWORD` | 관리자 페이지(`/admin`) 로그인 비밀번호 | 예: `dp2026!secure` (강력한 암호 권장) |

> ⚠️ **주의:** `ADMIN_PASSWORD`를 기본값으로 방치하고 `FLASK_ENV=production`을 설정하면 보안 필터링에 의해 관리자 페이지 접근이 차단되므로, 반드시 본인만의 안전한 비밀번호를 등록하여 사용하세요.

## 🔄 3. 배포(Deploy) 및 업데이트 운영 방법

배포 방식은 **자동 배포**와 **수동 배포** 두 가지가 있습니다.

### ① 자동 배포 (GitHub 연동)
*   **작동 방식:** 대표님이 컴퓨터에서 코드를 수정하여 GitHub의 `main` 브랜치에 `git push`를 하면, Render가 이를 감지하여 **자동으로 새로운 버전을 빌드하고 배포**합니다.
*   **장점:** 코드를 올리기만 하면 서버 관리를 따로 할 필요가 없어 매우 편리합니다.
*   **단점:** 빌드 도중 실수가 있으면 서버가 잠시 먹통이 될 수 있으나, Render는 빌드가 **성공해야만** 기존 서버를 교체하므로(Rolling Update) 무중단 서비스가 유지됩니다.

### ② 수동 배포 (Manual Deploy)
코드가 바뀌지 않았는데 서버를 재부팅하거나 강제로 다시 빌드하고 싶을 때 사용합니다.
1. Render 대시보드에서 `dreampocket` 서비스를 클릭합니다.
2. 우측 상단의 **[Manual Deploy]** 버튼을 클릭합니다.
   *   **[Deploy latest commit]:** 가장 최신 코드로 서버를 재시작합니다.
   *   **[Clear cache & deploy]:** 기존 빌드 찌꺼기(캐시)를 완전히 지우고 처음부터 깨끗하게 다시 빌드합니다. (패키지 오류 등이 생겼을 때 특효약입니다.)

## 🔎 4. 모니터링 및 트러블슈팅 (로그 확인법)

서비스 가동 중에 문제가 생기거나, 사용자가 접속이 안 된다고 할 때 대처법입니다.

### ① 실시간 서버 로그 (Logs) 확인
1. Render 대시보드 ➔ `dreampocket` 서비스 클릭 ➔ **[Logs]** 탭으로 이동합니다.
2. 서버에서 출력되는 모든 텍스트가 실시간으로 보입니다.
   *   `[Auto-Refresh Daemon] Starting background scholarship...`: 크롤러가 정상 작동 중임을 뜻합니다.
   *   `[Auto-Refresh Daemon] SUCCESS`: 수집 및 AI 정밀 분석이 완료되었을 때 출력됩니다.
   *   `GET / 200`: 사용자가 홈페이지에 성공적으로 접속했음을 뜻합니다.
   *   빨간색 글씨로 `Error` 또는 `Exception`이 발생하면 화면의 에러 메시지를 복사해서 저에게 가져다주시면 됩니다.

### ② 서버 작동 여부 확인 (Events)
*   Render의 **[Events]** 탭에서는 서버가 켜진 시간, 배포가 성공한 시간, 결제 관련 알림 등이 타임라인 형태로 표시되어 전체 가동 기록을 볼 수 있습니다.

## 💾 5. 데이터베이스 백업 및 다운로드
우리의 가장 소중한 자산은 수집된 장학금 데이터와 신청 보조 기록이 담긴 SQLite DB 파일입니다. 주기적으로 PC에 내려받아 백업하는 것을 권장합니다.

### 📥 DB 파일 로컬 PC로 다운로드하는 법
1. Render 대시보드 ➔ `dreampocket` 서비스 클릭 ➔ **[Shell]** 탭으로 이동합니다.
2. 브라우저에서 서버 내부 터미널로 즉시 연결됩니다.
3. 데이터베이스 상태를 확인하거나, 필요시 SFTP 툴 또는 Render 디스크 다운로드 기능을 이용해 `/app/data/antigravity_bot.db` 파일을 로컬 컴퓨터로 안전하게 보관할 수 있습니다.
   *   *(매달 1일이나 15일에 백업해 두는 캘린더 일정을 등록해 두는 것을 권장합니다.)*
